自动检查 **137 项通过，0 失败**。浏览器逐项验证 23 支枪的购买、原模型、皮肤及短点击扣弹，AWP 40° / 10° 两档、SG 553 瞄准、连续购买装备、烟雾和闪光效果通过；四名探员的选择、服务器确认与按阵营保存通过。

最终客户端在反复死亡和替换机器人测试中记录 **152 秒、77 次采样**，死亡数从 2 增至 23，全程保持连接与游戏控制；未观察到脚本错误或 WebGL 中断，JS 堆由 406 MiB 到 384 MiB，纹理峰值 587。这是短时间回归，不能替代所有设备上的长时间游玩。此前本轮的 132 秒短测和下文上一版的 **671 秒、97 次死亡**分别保留为不同构建的记录。

这轮还修复了高帧率下短点击在无物理步的渲染帧中被提前消费的问题，以及快速连续购买撞上服务器限频的问题。更换探员时保留观战位置；死亡中的角色等待重生再替换外观，避免重播倒地动作。

新主地址为 **[https://cs2.duskrain.cn/](https://cs2.duskrain.cn/)**，新主机配置为 **2 vCPU / 4 GiB 内存**。发布版本 **`20260909T032641Z`** 已通过 HTTPS、页面及最终脚本一致性校验；37 款武器外观、3 个道具和 4 名探员共 **44 个模型**全部通过公网 SHA-256 校验。真实双客户端完成 CT/T 共 30 次购买、阵营限制、射击、跳跃、武器皮肤与探员同步后正常退出。独立浏览器完成基础资源下载并进入对局，默认 SAS / 最低画质及 21 项 CT 商店检查通过，页面无脚本错误。

新服务检查记录为 0 重启、0 OOM、0 错误日志，可用内存约 3.19 GiB。首次基础资源下载约 184 MiB；并行下载时曾测到一次 1543 ms WSS 往返，下载结束后浏览器显示约 42 ms；随后 7 次独立 WSS 采样为 **38.62–52.72 ms，中位数 39.98 ms**。两者测试负载不同，不能把下载拥塞归因于游戏逻辑或 CPU。

旧站真人离开后，再次确认 0 人 / 0 房间才启用 `/dust2/` 到新站的重定向，保留路径与房间参数。仅替换游戏专用 Nginx include，首页与既有 vhost 的 SHA 保持不变；旧游戏进程保留为回退，不再承接旧入口的新连接。

增加服务器内存不等于解决客户端浏览器退出。用户报告的是**整个浏览器直接关闭**，该现象的根因仍未确认；目前没有证据可以据此归因于服务器性能，也不宣称已经消除。

## 玩家能看到的变化

- 死亡后保留战场，显示击杀者、武器、爆头信息与重生倒计时。死斗收到服务器重生状态后自动恢复操作，无需再次点「继续游戏」。
- 爆破死亡后先保留短暂死亡视角，再观察存活队友；默认左键、右键切换队友。Esc 仍可随时打开菜单并恢复鼠标，观战时也能从菜单返回。
- 网络断开显示断开代码及已知原因。若 WebGL 渲染上下文中断，显示恢复界面；浏览器恢复后可继续，或利用已缓存资源重新载入。
- 大厅和对局菜单提供「导出运行诊断」。记录只保存在本机，最多 60 条资源采样与 40 条事件，保留上一轮页面记录；不上传玩家信息、账号或凭据。

死亡与观战流程参考 [Valve Spectator UI](https://blog.counter-strike.net/2012/08/4839/) 与 [Steam 死亡镜头说明](https://help.steampowered.com/en/faqs/view/0E82-09BC-324C-CB12)，不是对官方闭源界面的逐像素复制。

## 上一版已确认并修复的缺陷

| 问题 | 修复 |
| --- | --- |
| 死亡主动退出 Pointer Lock，触发通用暂停菜单 | 把死亡状态与玩家主动打开菜单分开；死亡、重生只清空旧输入，不自动解锁鼠标 |
| 移除角色时遗留克隆骨骼纹理、脚底标记及动画缓存 | 释放实例独占资源，包括已从当前武器树移除的缓存模型；保留共享材质、几何与皮肤图像 |
| 暂停 AudioContext 时取消声音，等待延后的 `onended` 才断开节点 | 取消时立即幂等释放；自然播放完成走同一清理路径 |
| 特定畸形 join/buy 字段触发字符串强制转换异常，使服务器进程退出 | 在协议入口检查字段类型；拒绝坏消息后其他连接仍可正常工作 |
| 静态资源两次 stat 之间被替换，可能产生未处理拒绝 | 复用第一次文件查找的元数据；流读取失败终止该响应 |
| 拒绝过多连接时，关闭握手期间的非法帧可能没有错误处理器 | 在容量检查之前安装 socket 错误处理器 |

用户进一步明确，原始现象是整个浏览器关闭，而非仅返回大厅。这几项是可验证的缺陷。普通网页不会发送上述畸形消息；同一角色死亡重生也会复用模型。因此不能把它们直接当成用户全部闪退现象的唯一原因。

## 上一版验证：2026-09-08

- 自动化回归：**114 项通过，0 失败**。包含输入、跳跃、购买、皮肤、缓存、联机、死亡状态、资源生命周期与服务器容错。
- 浏览器功能检查：死亡时鼠标仍锁定且没有暂停菜单；重生立即可移动；Esc 恢复菜单和鼠标；爆破可观察并切换存活队友。
- 生命周期验证：重复移除 80 组角色，释放全部实例资源；实际 GLB 结构重复克隆/清理 50 次，SWAT 600/600、Hoodie 500/500、AWP 与手臂各 100/100 骨骼纹理释放，共享资源保留。
- 服务器隔离压力：4 房间、40 名角色，其中 32 个机器人，真实 WebSocket 运行 90 秒；RSS 约 131–132 MiB。之后执行 600 秒游戏时间的加速模拟，实际耗时 176.7 秒；这部分不是 10 分钟真实联网运行。事件和路径保持有界，全部客户端离开后房间及连接归零。
- 修复后服务器短测：40 个连接均正常保持，0 提前断开、0 传输或协议错误；退出后 GC 堆内存约 16 MiB。另验证慢连接写队列拥塞只断开该连接，其他玩家仍正常。

上一版独立无界面 Chrome 以 2560×1273 连续运行 **671 秒**，8 个机器人，每 7 秒触发一次真实服务器死亡、每 21 秒替换全部机器人，共记录 **97 次死亡**。335 个采样全部保持连接；页面外监听未记录 crash 或 close，诊断未记录脚本错误或 WebGL 中断。最后 120 秒纹理保持 **612**，几何资源在 1928–1936 间随瞬时效果变化，JS 堆为 245–332 MiB，未出现随替换次数持续增长。此测试不是所有设备、全部浏览器与无限时长的保证，也不包含本次新增探员和道具的完整覆盖。

上一版实际 WebGL 丢失/恢复测试通过：显示恢复界面、重新生成武器环境反射，地图与武器恢复渲染后能重新锁定鼠标继续；没有脚本异常。旧站 `/dust2/` 当时部署为 `20260908T142657Z`，HTTPS、静态资源和双客户端 WSS 的移动、购买、皮肤与跳跃验证通过，测得一次往返 63 ms。2395 个发布文件经过校验，站点原首页哈希保持不变。该结果不代表新域名已完成迁移验收。

## 上一版服务器与本机资源记录

2026-09-08 检查时，旧站游戏服务没有异常重启、内存限制触发或内核 OOM 记录。旧主机为 2 CPU / 2 GiB，游戏进程约 138 MiB；单房间 8 机器人实测 60 秒，RSS 保持 139 MiB，收到 942 次快照，结束后房间归零。**这些证据不指向当时的服务器性能不足**，也不代表已经验证了所有公网满载场景。

本机检查发现过 C 盘剩余空间为 0、16 GiB 内存仅约 0.93 GiB 空闲，以及 8 GiB 显存使用约 7.1 GiB。关闭本任务遗留的两个临时浏览器会话后，C 盘恢复约 6.4 GiB 可用空间。此操作没有清除正常浏览器的用户数据。

上一版完整地图 510 张纹理以 RGBA8 加 mipmap 估算约 1.22 GiB；当时默认武器与手臂再约 0.21 GiB，另外还有几何、阴影、帧缓冲和驱动开销。这是旧资源尺寸估算，并非当前版本单页实测显存。多个高负载网页会共同占用本机内存与显存；当时保留原贴图和画质，本次则按用户要求将初始画质设为最低，并保留调节入口。

一次有界面测试在约 7 分半后被空白页打断：之前采样无脚本错误或 WebGL 中断，自动化工具在页面关闭或崩溃后都可能重建空白页，现有记录无法区分两者。因此该次不计为完整通过，后续独立会话增加页面外的 crash、close 和导航监听复测。磁盘和显存压力与中断同时被观察到，但尚不能证明因果关系。
